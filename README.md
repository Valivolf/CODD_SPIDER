# Календарь работ

Веб-приложение диспетчерской службы для планирования выездов, учёта комплексов фотовидеофиксации (АПК), работы бригад и монтёров, оборудования и отчётов. Дополнительные компоненты — бот ВКонтакте, робот Яндекс.Карт, локальные ИИ-службы и Windows-агент ИИ.

Основной сценарий развёртывания — Docker Compose на Linux. Для сервера без интернета Docker-образы и установочные файлы заранее собираются на машине с интернетом, проверяются и переносятся отдельным архивом.

## Возможности

- Календарь выездов, бригады, исполнители, виды работ и история выездов.
- Справочник АПК: статусы и доступность, карточки комплексов, группы, SIM-карты, оборудование, файлы и фотографии.
- Отчёты, печатные планы-задания, импорт и выгрузка Excel, импорт данных и карт.
- Склад и движение оборудования, уведомления, статистика, чат диспетчеров.
- Бот ВКонтакте для монтёров: задания, сообщения и отчёты. Бот не хранит отдельную рабочую базу — он обращается к приложению.
- Проверка связи с комплексами, мониторинг, журнал событий безопасности и контроль состояния системы.
- По желанию: ведение карт бригад в Яндекс.Конструкторе, голосовые итоги и помощник по данным на локальных ИИ-службах.
- Веб-страница с играми; доступ к отдельным разделам и действиям определяется правами роли.

### Основные слои приложения

1. Браузер загружает страницы из `templates/` и скрипты из `static/js/`.
2. Скрипты обращаются к FastAPI через `/api/*`.
3. API-маршруты проверяют пользователя и права, затем передают работу в сервисы и репозитории.
4. Репозитории работают с SQLite через `aiosqlite`. Схема создаётся и поэтапно обновляется приложением при запуске.
5. Независимые циклы приложения выполняют фоновые операции: резервное копирование, мониторинг, обслуживание фото, синхронизацию карт, обработку отчётов и обслуживание очереди ИИ.

Для нового API-маршрута требуется правило доступа в `app/core/permissions.py`. В локальном комплекте проверок есть обход API на соответствие таблице прав, но `docs/compliance/` исключён из Git и эти проверки не входят в опубликованную копию.

## Контейнеры и данные

| Сервис Compose | Назначение | Запуск |
|---|---|---|
| `lan-calendar` | FastAPI-приложение. Использует `lan-calendar:latest`. | По умолчанию |
| `codd-bot` | Бот ВКонтакте из того же образа приложения. | По умолчанию |
| `caddy` | HTTPS, сертификат внутреннего центра и проксирование к приложению. | По умолчанию |
| `yandex-robot` | Playwright и Chromium для карт и загрузки файлов Яндекс Форм. | Профиль `robot` |
| `llm` | Локальная языковая модель llama.cpp. | Профиль `ai` |
| `asr` | Распознавание речи faster-whisper. | Профиль `ai` |

Приложение слушает порт 8000 внутри контейнера; на хосте он доступен только на `127.0.0.1`. Пользователи подключаются через Caddy по HTTP/HTTPS (80/443). Контейнеры `llm` и `asr` подключены к внутренней сети `ai_internal`, у которой нет выхода наружу.

Рабочие данные находятся вне образа:

- `data/calendar.db` — SQLite-база;
- `data/` — также автоматически создаваемые ключи приложения, бота и шифрования;
- `backups/` — резервные копии базы;
- `.env` — настройки приложения и секреты;
- `bot.env` — токен ВКонтакте и ключ связи бота с приложением;
- `ai-models/` — модели ИИ, если установлен отдельный ИИ-архив;
- тома Compose — профиль браузера робота и данные Caddy.

Обновление контейнера не должно заменять базу и секреты. Не удаляйте `data/`, `backups/`, `.env`, `bot.env` или тома Compose при обновлении. Файл `.env.example` содержит пример настроек, а не рабочие секреты.

## Запуск для разработки

Основной сервер разработки — Linux или Windows с Python 3.12+ и установленными зависимостями из `requirements.txt`. Для локального запуска:

```text
python -m venv .venv
```

В Windows активируйте `.venv\Scripts\activate`, в Linux/macOS — `source .venv/bin/activate`. Затем:

```text
python -m pip install -r requirements.txt
```

Создайте локальный `.env` на основе `.env.example`, настройте `ADMIN_USERNAME` и задайте собственный `ADMIN_PASSWORD`. Не используйте примерный пароль в рабочей среде. Локальный сервер запускается так:

```text
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте `http://127.0.0.1:8000`. При первом запуске приложение подготовит базу и создаст администратора, если пользователей ещё нет. Бот не запускается вместе с этим сервером: для него нужны отдельные значения в `bot.env` и работающий API приложения.

Для Compose основное приложение и бот используют один образ. Дополнительные проверки ролей и безопасности из локального рабочего окружения находятся в `docs/compliance/tests/`, но весь каталог `docs/compliance/` исключён из Git и в эту публикацию не входит. Часть исторических интеграционных проверок также хранилась вне репозитория; перед выпуском проверяйте, какие именно тесты доступны в вашей копии.

## Обновление на сервере без интернета

### Что необходимо заранее

- **Сборочная машина** с Linux, Bash, Docker и доступом к интернету для загрузки базовых образов и Python-пакетов при сборке.
- **Рабочий сервер** с Linux, Docker Engine и Docker Compose v2. На нём уже должны быть настроены каталог проекта (по умолчанию `/opt/lan_calendar`), `.env`, `bot.env` и постоянные каталоги данных.
- Канал переноса архива со сборочной машины на сервер: `scp` по доступной сети либо физический носитель.

На офлайн-сервере не нужно выполнять `docker build`, загружать образы из Docker Hub, ставить Python-пакеты из интернета или клонировать Git-репозиторий. На сервер доставляются уже собранный образ и файлы Compose.

Описанный ниже пакет и `install.sh` предназначены для **обновления уже установленного приложения**. Архив приложения не содержит базовый образ Caddy, Docker Engine, конфигурацию секретов и первоначально подготовленные каталоги сервера; для новой установки эти компоненты нужно подготовить отдельно, тоже без расчёта на скачивание образов на целевом сервере.

### 1. Собрать архив приложения на машине с интернетом

Получите нужную версию исходников на Linux-сборочной машине и из корня проекта выполните:

```bash
bash scripts/offline/make_bundle.sh app /opt/offline-out
```

Скрипт собирает образ `lan-calendar:latest`, сохраняет его как сжатый Docker-архив и создаёт файл вида:

```text
/opt/offline-out/lan-calendar-app-ГГГГММДД-ЧЧММ.tar
```

Внутри архива находятся:

- `lan-calendar.tar.gz` — образ приложения и бота;
- актуальные файлы Compose, Caddy и Dockerfile;
- актуальный код `robot/` (но не тяжёлый образ Chromium);
- `install.sh`, `selftest.sh`, инструкции и контрольные суммы;
- метка `BUILD` и `CODE.sha256` для проверки версии кода.

Сборка использует Dockerfile из `docker/Dockerfile`, устанавливает системный `iputils-ping`, Python-зависимости из `requirements.txt` и копирует код `app/`, `bot/`, `static/`, `templates/` внутрь образа. На машине-сборщике должны быть доступны интернет, Docker и место для образов и итогового архива.

Посмотрите точное имя архива и вычислите его контрольную сумму:

```bash
ls -lh /opt/offline-out/lan-calendar-app-*.tar
sha256sum /opt/offline-out/lan-calendar-app-ГГГГММДД-ЧЧММ.tar
```

Подставляйте точное имя файла, а не `*`: если архивов несколько, легко отправить старую сборку. При переносе через Windows можно сверить контрольную сумму командой PowerShell:

```powershell
Get-FileHash .\lan-calendar-app-ГГГГММДД-ЧЧММ.tar -Algorithm SHA256
```

### 2. Перенести архив на офлайн-сервер

Если сборочная машина может подключиться к серверу по SSH:

```bash
scp /opt/offline-out/lan-calendar-app-ГГГГММДД-ЧЧММ.tar USER@SERVER:/tmp/
```

Иначе перенесите этот файл на сервер физически. Сверьте SHA-256 с контрольной суммой, вычисленной на сборочной машине. Перед установкой проверьте свободное место и убедитесь, что `.env`, `bot.env`, `data/` и `backups/` находятся в каталоге проекта.

### 3. Проверить и распаковать пакет на сервере

Команды выполняются на Linux-сервере. Замените имя файла на точное:

```bash
cd /tmp
sha256sum lan-calendar-app-ГГГГММДД-ЧЧММ.tar
tar -xf lan-calendar-app-ГГГГММДД-ЧЧММ.tar
cat lan-calendar-app/BUILD
cd lan-calendar-app
sudo bash install.sh --check
```

Сравните SHA-256 с результатом на сборочной машине. Команда `--check` запускает проверки без установки. Не распаковывайте пакет поверх `/opt/lan_calendar`: пакет распаковывается во временную папку `lan-calendar-app`, а его установщик обновляет действующий проект отдельно.

### 4. Установить обновление

Когда предварительные проверки пройдены, выполните:

```bash
sudo bash install.sh
```

Если проект размещён не в `/opt/lan_calendar`, передайте путь:

```bash
sudo bash install.sh /путь/к/проекту
```

Установщик без обращения к интернету:

1. Проверяет файлы архива по `SHA256SUMS`.
2. Сохраняет копию текущей базы в `backups/before-update-*.db`.
3. Помечает предыдущий образ как `lan-calendar:previous` и загружает новый образ из архива.
4. Обновляет файлы `docker/` и код робота; не заменяет секреты и настройки `.env`/`bot.env`.
5. Перезапускает приложение и бота без сборки и скачивания образов.
6. Проверяет, что запущен именно загруженный образ, выполняет самопроверку установки и показывает результат.

Миграции базы выполняет приложение при запуске. Установщик сохраняет копию базы заранее, но резервная копия не заменяет регулярное резервное копирование.

### 5. Проверить результат

Убедитесь, что установщик закончил проверку сообщением `ВСЁ ГОТОВО`, а основные контейнеры работают:

```bash
cd /opt/lan_calendar/docker
sudo docker compose ps
sudo docker ps
sudo docker logs --tail 100 lan-calendar
sudo docker logs --tail 100 codd-bot
```

Повторная самопроверка без обновления:

```bash
cd /tmp/lan-calendar-app
sudo bash install.sh --check
```

Приложение должно отвечать локально на сервере:

```bash
curl -fsS http://127.0.0.1:8000/healthz
```

Затем проверьте страницу входа через адрес HTTPS, используемый организацией. Caddy при обычном обновлении приложения не пересобирается и не перезапускается; установщик отдельно сообщает, если его конфигурация изменилась и требуется дополнительное действие.

### Откат приложения

Если после обновления требуется вернуться к предыдущему образу:

```bash
sudo docker tag lan-calendar:previous lan-calendar:latest
cd /opt/lan_calendar/docker
sudo docker compose up -d --no-build lan-calendar codd-bot
```

Само возвращение старого образа **не откатывает** изменения схемы базы. Восстановление резервной копии базы может удалить данные, добавленные после обновления; выполняйте его отдельно только после проверки нужной копии и согласования.

## Дополнительные архивы

Приложение, браузерный робот и ИИ — отдельные офлайн-пакеты:

| Пакет | Сборка на машине с интернетом | Особенности |
|---|---|---|
| Приложение | `bash scripts/offline/make_bundle.sh app /путь/к/выходу` | Нужен при каждом обновлении приложения. Включает новый код робота. |
| Робот Яндекс.Карт | `bash scripts/offline/make_bundle.sh robot /путь/к/выходу` | Большой образ с Chromium; обычно переносится один раз или при изменении образа. Приложение должно быть установлено раньше. |
| ИИ | `bash scripts/offline/make_bundle.sh ai /путь/к/выходу` | Отдельный большой пакет: образы llama.cpp и faster-whisper, файлы моделей. В `ai-models/` заранее должны быть необходимые модели. |

`all` — режим по умолчанию — собирает пакет приложения и пакет робота. ИИ в `all` не входит. Для каждого дополнительного архива используйте его собственную инструкцию `README.txt` и установщик `install.sh`. На рабочем сервере применяйте пакеты в порядке: приложение, затем при необходимости робот и/или ИИ.

Для включения уже доставленных компонентов используются профили Compose:

```bash
cd /opt/lan_calendar/docker
sudo docker compose --profile robot up -d --no-build yandex-robot
sudo docker compose --profile ai up -d --no-build llm asr
```

Обычно эти действия уже выполняются соответствующими офлайн-установщиками. Не запускайте `--build` на сервере без интернета.

## Проверка и устранение неполадок

- Состояние контейнеров: `sudo docker compose ps` из `/opt/lan_calendar/docker`.
- Приложение: `sudo docker logs --tail 200 lan-calendar`.
- Бот: `sudo docker logs --tail 200 codd-bot`.
- Caddy: `sudo docker logs --tail 200 lan-calendar-caddy`.
- Робот: `sudo docker logs --tail 200 yandex-robot`.
- ИИ: `sudo docker logs --tail 200 lan-calendar-llm` и `sudo docker logs --tail 200 lan-calendar-asr`.
- Ошибка контрольной суммы — остановитесь и перенесите архив заново.
- Ошибка `Нет доступа к Docker` — запускайте установщик через `sudo` и проверьте Docker Engine.
- Ошибка `Не найден docker compose` — установите на сервере Compose v2 до переноса обновления.
- Если не проходит самопроверка, сохраните весь её вывод и журналы проблемных контейнеров. Не удаляйте базу и ключи в попытке «починить» установку.

## Секреты и личные данные

- Не добавляйте в Git `.env`, `bot.env`, `docker/.env`, `data/`, `backups/`, базы данных, ключи, файлы моделей и собранные EXE.
- `.gitignore` исключает локальные данные, ключи бота и робота, резервные копии, сборки и локальные настройки.
- Перед первой настройкой создайте собственный пароль администратора. Не используйте пароль из демонстрационного шаблона.
- `.env` может содержать ключ шифрования базы и секрет подписи сессий; `bot.env` — токен ВКонтакте. Храните их отдельно от исходного кода и передавайте только защищённым способом.
- Ключ шифрования полей и база нужны вместе: резервная копия базы без соответствующего ключа не позволит прочитать зашифрованные значения.
- Офлайн-архив обновления содержит исполняемый образ приложения и код, но не базу, ключи, токен бота или рабочие `.env`. Не подменяйте его архивом всей папки проекта.
