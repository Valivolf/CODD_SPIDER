ОБНОВЛЕНИЕ ПРИЛОЖЕНИЯ «КАЛЕНДАРЬ РАБОТ» НА СЕРВЕРЕ БЕЗ ИНТЕРНЕТА
================================================================

Создание архива обновления в Windows:
  На компьютере со свежим кодом откройте PowerShell в корне проекта и выполните:

        .\scripts\offline\make_bundle.cmd

  Скрипт make_bundle.cmd запускает make_bundle.ps1. Docker Desktop должен быть установлен. Если Docker Engine
  не запущен, скрипт попробует запустить Docker Desktop и подождёт до 120 секунд. Для сборки нужны доступные
  Docker-образы и зависимости (при необходимости Docker скачает их из интернета).

  По умолчанию результат появится в папке offline-out в корне проекта:
        offline-out\lan-calendar-app-ГГГГММДД-ЧЧММ.tar

  Можно указать папку для результата:
        .\scripts\offline\make_bundle.cmd app "D:\Обновления"

  Параметр app можно опустить; update — равнозначный вариант. Скрипт собирает образ приложения и бота,
  упаковывает его вместе с файлами docker/, установщиком и проверками. Пакет не содержит браузер и ИИ.
  Если в Docker уже существует контейнер lan-calendar, скрипт также обновит локальные контейнеры приложения
  и бота на этом компьютере — учитывайте это, если на нём запущено рабочее окружение.

  Windows-сборщик не добавляет в архив папку robot/ и не обновляет код робота на сервере. Для обновления
  кода робота используйте пакет, собранный Linux-скриптом make_bundle.sh app; отдельный большой архив
  yandex-robot нужен для установки или обновления самого образа робота с браузером.

  После сборки перенесите полученный .tar на Linux-сервер и продолжите с шага «Куда положить и что запустить»
  ниже. Серверные команды установки выполняются на Linux, а не в Windows.

Что внутри (папка lan-calendar-app):
  lan-calendar.tar.gz  готовый образ Docker приложения (lan-calendar:latest, бот в том же образе)
  docker/              файлы из папки docker проекта: docker-compose.yml, Dockerfile, Dockerfile.caddy,
                       Caddyfile, caddy-entrypoint.sh — как раньше, ложатся поверх старых
  install.sh           установка одной командой
  SHA256SUMS           контрольные суммы (скрипт проверит файлы сам)

Куда положить и что запустить (на рабочем сервере):
  1. Скопируйте файл lan-calendar-app-<дата-время>.tar на сервер — любое место, например домашняя папка.
  2. Сначала уберите старую распакованную папку, затем распакуйте ИМЕННО этот файл (по имени, без «*»:
     со звёздочкой при нескольких архивах tar берёт первый — старый) и запустите
     (папка проекта по умолчанию /opt/lan_calendar):

        rm -rf lan-calendar-app
        tar xf lan-calendar-app-ДАТА-ВРЕМЯ.tar
        bash lan-calendar-app/install.sh

     Команда cat покажет метку сборки (ДАТА-ВРЕМЯ из имени файла); установщик повторит её первой строкой
     «Сборка пакета: …» и в конце сверит, что в контейнере работает код именно этой сборки.

     Если проект лежит не в /opt/lan_calendar:   sudo bash install.sh /путь/к/проекту

  Скрипт сам: проверит файлы, сделает копию базы (backups/before-update-….db), загрузит образ
  (прежний останется как lan-calendar:previous), заменит файлы в docker/ (старые сохранит как *.bak-…)
  и перезапустит приложение с ботом. Интернет не нужен. Caddy не перезапускается (он не менялся);
  если файлы Caddy в обновлении отличаются — скрипт об этом предупредит.

  Образ содержит всю текущую версию приложения; базу при первом запуске оно приводит к своей схеме
  само (копия для отката делается заранее).

Робот карт (браузер) — ОТДЕЛЬНЫЙ архив yandex-robot-<дата>.tar. Он большой и нужен один раз; при
обычных обновлениях приложения его заново возить не нужно. Свежий КОД робота (папка robot/) ездит в
этом, маленьком, архиве: если робот уже установлен, скрипт сам обновит его и перезапустит.
Карты бригад при включённой автоматике (Настройки → «Яндекс-аккаунт для карт») создаются и ТОЧЕЧНО правятся
приложением само (ссылка не меняется), удаляются только по сроку хранения — подробности в robot/README.md.

Откат:
  docker tag lan-calendar:previous lan-calendar:latest
  cd /opt/lan_calendar/docker && docker compose up -d --no-build lan-calendar codd-bot

Журнал:  docker logs lan-calendar
